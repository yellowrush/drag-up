## White Screen Bug Fix (H5 + WeChat MP)
- Root cause: `getCurrentInstance` used in `game-canvas.vue` but removed from `vue` import → `ReferenceError` in `<script setup>` → Vue silently catches, component never renders → empty `div#app`
- Second bug: `Storage` object in `storage.js` was missing game-specific methods (`getCurrentLevel`, `saveCurrentLevel`, `markLevelCompleted`) — they were standalone `export function` instead of methods on the `Storage` object, but `game-engine.js` called `Storage.getCurrentLevel()` etc.
- Also fixed: `onMounted`/`onUnmounted` incorrectly imported from `vue` instead of `@dcloudio/uni-app` in all 3 Vue files — **THIS WAS WRONG, see correction below**
- Also fixed: `defineProps`/`defineEmits` incorrectly imported from `vue` in `level-select.vue` (they are compiler macros, no import needed)
- Also fixed: `game-canvas.vue` used `uni.getElementById` (doesn't exist) → replaced with `uni.createSelectorQuery().in(instance.proxy).select('#gameCanvas').fields({node:true}).exec()`
- Added `h5` config to `manifest.json` (hash router, title)
- **CORRECTION**: `onMounted`/`onUnmounted` are Vue 3 standard lifecycle hooks — they MUST be imported from `vue`, NOT from `@dcloudio/uni-app`. The earlier "fix" that moved them to `@dcloudio/uni-app` was wrong and caused `SyntaxError: does not provide an export named 'onMounted'`. Only uni-app-specific hooks like `onLoad`, `onShow`, `onReady`, `onHide` come from `@dcloudio/uni-app`.
- Key lesson: In uni-app Vue 3, `vue` exports: `ref`, `reactive`, `computed`, `watch`, `onMounted`, `onUnmounted`, `getCurrentInstance`, etc. `@dcloudio/uni-app` exports: `onLoad`, `onShow`, `onReady`, `onHide`, `onPullDownRefresh`, `onReachBottom`, etc. Do NOT mix them up.
- Key lesson: Vue 3 `<script setup>` swallows ReferenceErrors silently, causing blank screens with no console error.
- **REAL root cause of H5 white screen**: `index.html` was missing `<script type="module" src="/main.js"></script>` — Vite had no entry point, no JS was ever loaded, Vue never mounted. This was the actual reason `div#app` was empty with zero console errors.
- Fixed `index.html` to include the module script entry tag + viewport coverSupport script (standard uni-app H5 template)

## TypeError + Touch Drag Fix
- **Bug**: `index.vue:109` — `gameCanvas.value.gameEngine.value.onLevelComplete` threw `TypeError: Cannot set properties of undefined`. `defineExpose({ gameEngine })` auto-unwraps the ref, so `.value` was accessing `undefined` on the already-unwrapped GameEngine instance. Fix: removed `.value`.
- **Bug**: Touch coordinates used `event.touches[0].x/.y` but H5/browser Touch API uses `clientX`/`clientY`. Added `getTouchPoint()` helper with fallback for both platforms.
- **Bug**: `checkIsOnCub()` didn't account for maze rotation — cub position was wrong after rotating. Fixed to apply rotation matrix.
- **Bug**: `FlyWheel.integrate()` was never called in `update()` — rotation forces via `applyForce()` had no effect. Added `this.flyWheel.integrate()` to update loop.
- **Bug**: `onGameReady` function was nested inside `onMounted` callback — not accessible from template `@ready` binding. Moved to module scope.
- Replaced fragile `setTimeout(1000)` with `@ready` emit from `game-canvas.vue` → parent receives engine instance directly.
- Added mouse event support (`@mousedown/@mousemove/@mouseup`) for H5 desktop testing — converts to touch-like events for game engine.
- Added hover detection (mouse over cub highlights it).
- Added `touch-action: none` CSS to prevent browser scroll interference.
- Key lesson: In Vue 3 `<script setup>`, `defineExpose({ someRef })` auto-unwraps refs when accessed from parent template ref. Parent gets the unwrapped value directly, NOT the ref object. Do NOT add `.value`.
